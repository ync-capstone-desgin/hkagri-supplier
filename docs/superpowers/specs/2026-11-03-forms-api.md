# #6 사내 양식 자료실 API 설계

- 목적: 업체와 무관한 사내 공용 양식을 게시글과 여러 첨부로 공유한다. 화면은 #7 범위다.
- 사용자 선택: 게시글·파일을 한 요청/트랜잭션으로 저장한다. 하나라도 실패하면 DB 변경과 새 디스크 파일을 모두 취소한다. 게시글 먼저 생성 후 파일별 저장 방식은 미완성 게시글이 남으므로 사용하지 않는다.
- 게시글: 제목(필수, 200자), 설명(선택, 5000자), 분류(CONTRACT 계약 양식 / CHECKLIST 점검표 / OTHER 기타), 작성·수정자 및 시각. 파일 없는 게시글도 허용한다.
- API: GET /api/forms?keyword=&category=&page=0&size=20, GET /api/forms/{id}, POST /api/forms, PUT /api/forms/{id}, DELETE /api/forms/{id}.
- 등록/수정은 multipart: JSON `post`(title, description, category, removeFileIds), 반복 `files`. 수정 시 지정한 기존 파일만 삭제하고 나머지는 유지한다. 교체는 삭제와 새 업로드를 한 요청으로 보낸다. 다른 게시글 파일 ID는 거절한다.
- 다운로드는 기존 GET /api/files/{id}/download를 사용한다. 파일 저장·검증·롤백 정리도 FileService를 재사용한다. 기존 파일 ID를 임의로 연결하는 API는 만들지 않는다.
- 등록·수정·삭제: ADMIN, MANAGER. 조회·다운로드: 로그인 사용자. Q-10 확정 전 이슈의 기본 권한을 따른다.
- 게시글 삭제와 첨부 삭제는 논리 삭제: 조회·다운로드에서는 제외하고 감사 기록과 저장 내용은 보존한다. 수정/삭제는 게시글 행 잠금으로 직렬화한다.
- form_post와 form_post_file(파일 ID UNIQUE) 테이블을 V8에 추가한다. #29 V6와 #30 V7이 적용된 뒤 V8을 적용한다. 미머지 마이그레이션을 복제하지 않으며 별도 Testcontainers DB로 검증한다.
- 파일당 20MB, 요청 전체 기본 21MB 등 기존 파일 정책을 따른다. 새 라이브러리·화면·운영 배포는 포함하지 않는다.
