# 인증 종류 관리 (#36)

## 목적과 범위
한국농산 관리자가 인증 종류를 직접 추가·이름 변경·비활성화·재활성화한다. 기존 인증과 갱신 이력은 그대로 보존한다. 실행 범위는 사용자가 승인한 [이슈 #36](https://github.com/ync-capstone-desgin/hkagri-supplier/issues/36)이며, 실제 회사 데이터 등록과 #37 적용 대상 입력은 제외한다.

## 구현 방식과 선택 근거
- 인증 목록의 관리자 전용 버튼에서 관리 모달을 연다. 별도 설정 페이지보다 이동이 적고, 기존 Ant Design 모달·표를 재사용할 수 있다. 화면 배치는 구현 판단이다.
- 기존 GET `/api/cert-types`는 모든 종류를 반환하며 `active`를 추가한다. 검색 필터는 비활성 종류도 표시하고 등록·갱신은 활성 종류만 선택한다.
- 변경 API는 기존 ADMIN 전용 경로 `/api/admin/cert-types` 아래에 둔다. POST는 이름, PUT `/{code}`는 이름, PATCH `/{code}/active`는 활성 상태만 받는다. 독립 검토에서 확인한 서로 다른 관리자 변경의 덮어쓰기를 막기 위해 변경 필드를 분리한다. 물리 삭제 API는 제공하지 않는다.
- 신규 코드는 서버가 30자 이내의 불변 식별자로 생성한다. 표시 이름은 100자 이내이며 공백을 정리한다. 모든 공백을 제거하고 소문자로 만든 비교 키에 DB 유일 제약을 둬 동시 중복도 차단한다.
- 기존 인증의 종류를 그대로 둔 수정은 비활성 종류도 허용한다. 새 인증·갱신·다른 비활성 종류로 변경은 차단한다. 갱신 시 원래 종류가 비활성이면 활성 종류를 고를 수 있게 한다.
- 종류 변경 뒤 관련 인증·업체·만료 화면의 쿼리를 갱신한다. 선택 목록은 창을 다시 열거나 포커스를 되찾을 때도 갱신한다.
- 새 Flyway V10을 사용한다. V9는 진행 중인 자료실 PR #35에서 사용 중이므로 피한다. 기존 마이그레이션과 인증 외래키는 수정하지 않는다.

## 검증
실제 PostgreSQL 통합 테스트로 ADMIN 권한, 이름 검증·중복, 비활성 종류 선택 제한, 갱신 실패 롤백, 기존 기록·링크 보존을 확인한다. 프론트엔드 빌드·린트와 별도 개발 서버의 브라우저 흐름으로 관리·등록·검색 동작을 확인한다. 자료실 미리보기 서버와 DB는 유지한다.
