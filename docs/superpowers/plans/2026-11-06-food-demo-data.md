# 식품 업종 가상 샘플 정비 계획

> **For agentic workers:** Use superpowers:executing-plans to implement each step with verification.

**Goal:** #14 시연 데이터를 과일 원료·식품 가공·포장재·물류 업체의 실제적인 업무 형태에 맞춘다.
**Spec:** https://github.com/ync-capstone-desgin/hkagri-supplier/issues/14
**Architecture:** 기존 dev 전용 `DevDataSeeder`의 가상 예시만 변경한다. 업종은 기존 업체 비고에 표시하고 업체 유형에 맞는 계약·인증·적용 대상을 연결한다.
**Tech Stack:** Java/Spring Boot/JPA/PostgreSQL, 기존 React 화면.

## 제약과 선택

- 실제 한국농산 자료·업체명·거래·연락처·인증번호를 복사하지 않는다. 업체명은 `가상-`, 인증번호는 `DEMO-`로 표시한다.
- 운영 기준정보를 변경하는 마이그레이션은 만들지 않는다. 새 dev DB의 예시에 FSSC 22000을 추가하고 기존 식품 관련 종류를 활용한다. 회사 공식 인증 목록의 확정은 별개다.
- 기존 사용자 또는 업체가 있으면 시드를 실행하지 않는다. 기존 미리보기 DB를 지우지 않고 같은 PostgreSQL 안의 별도 빈 DB에서 시연한다.
- 업체 20곳·계약 30건·인증 30건과 기존 만료 경계·무기한·만료일 없음·처리 중 사례를 유지한다.
- #39의 적용 대상 기능을 포함한 `54c522b`에서 별도 브랜치로 작업한다. 서버는 5175/8081 두 개를 재사용한다.

## 검토할 경계

- 포장재·물류 업체에 농가·식품 가공 인증이 무작위로 붙지 않는지.
- 같은 업체의 HACCP를 서로 다른 적용 대상으로 구분할 수 있는지.
- 재시작하거나 기존 사용자 없이 업체 자료만 존재해도 시연 데이터가 섞이지 않는지.
- 날짜 경계와 비어 있는 계약번호·적용 대상 사례가 유지되는지.

## 검증 기록 (2026-11-06)

- 기존 구현에서 새 테스트 5개 중 4개가 의도한 이유로 실패했다. 수정 후 관련 5개, 전체 125개가 실패·오류·누락 없이 통과했고 `bootJar`도 성공했다.
- 별도 빈 시연 DB에 사용자 4명·업체 20곳·계약 30건·인증 30건이 생성됐다. 기존 DB의 업체 23곳·계약 30건·인증 34건은 보존했다.
- 실제 Chrome에서 주요 화면 11개, 적용 대상 2종 검색, 업체 상세의 HACCP 2개 대상, VIEWER 조회 전용을 확인했다. 브라우저 오류 0. 로컬 만료 점검으로 알림 28건을 생성했다.
- 원본 기업 파일과 DB 덤프는 추가하지 않았다. 화면 캡처 2장은 새 가상 DB만 사용했다. 프런트엔드 코드는 수정하지 않았다.
- 별도 Flyway 점검은 임시 파일과 일회용 PostgreSQL에서 수행했다. V1~V11 신규 적용·V8에서 V11 업그레이드는 통과했고 V9 뒤늦은 추가의 검증 오류를 재현했다. 기존 마이그레이션이나 DB 이력은 수정하지 않았다.
