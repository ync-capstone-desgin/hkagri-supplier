# 협력업체·계약·인증 삭제 (#44)

잘못 등록한 협력업체·계약·인증을 지운다. 행을 실제로 지우지 않고 **지운 표시만 남긴다.** 삭제한 건은 목록·상세·만료 현황·대시보드·알림함·엑셀에서 모두 빠진다.

## 사용 방법

- **계약·인증**: 계약 관리·인증 관리 목록 또는 업체 상세의 계약·인증 탭에서 행의 **삭제**를 누르고 확인한다.
- **협력업체**: 업체 상세 화면 오른쪽 위의 **삭제**를 누르고 확인한다. 삭제되면 목록으로 돌아간다.
- 관리자와 담당자만 삭제할 수 있다. 조회자에게는 삭제 버튼이 보이지 않고 서버도 403으로 막는다.

## 규칙

| 상황 | 동작 |
|---|---|
| 계약·인증을 삭제 | 그 건의 첨부 파일도 함께 지운 표시가 되고, 그 건에 대한 알림은 알림함에서 없어진다 |
| 갱신으로 등록한 건을 삭제 | 그 건만 지우고, 갱신 전 건이 다시 **현재 건**이 된다. 처리상태는 "미착수"로 돌아간다 |
| 이전 이력(갱신 전 건)을 삭제 | 409로 막는다. 현재 건을 삭제하면 이전 건이 현재 건이 되므로, 그 뒤에 다시 삭제한다 |
| 계약·인증이 남은 협력업체를 삭제 | 409와 함께 남은 건수를 안내한다. 이전 이력도 건수에 포함한다 |
| 계약·인증이 없는 협력업체를 삭제 | 업체에 올린 일반 자료도 함께 지운 표시가 된다 |

## API

| 요청 | 응답 |
|---|---|
| `DELETE /api/suppliers/{id}` | 204. 계약·인증이 남아 있으면 409 |
| `DELETE /api/contracts/{id}` | 204. 이전 이력이면 409 |
| `DELETE /api/certifications/{id}` | 204. 이전 이력이면 409 |

없거나 이미 삭제된 건은 404, 조회자는 403이다.

## DB

`V12__soft_delete.sql`이 `supplier`·`contract`·`certification`에 `deleted_at`, `deleted_by`를 추가한다. 세 엔티티는 `@SQLRestriction("deleted_at is null")`로 모든 조회에서 삭제된 행을 뺀다.

실수로 지운 건은 DB에서 `deleted_at`, `deleted_by`를 null로 되돌리면 다시 보인다. 되살리기 화면은 없다. 갱신 건을 지워 이전 건이 현재 건으로 돌아간 경우에는 이전 건의 `active`도 함께 되돌려야 한다. 함께 지워진 첨부 파일은 `stored_file`에서 같은 방법으로 되돌리고, 없어진 알림은 다음 만료 점검 때 기준에 맞으면 다시 만들어진다.
