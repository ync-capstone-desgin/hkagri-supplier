# 협력업체·계약·인증 삭제 (#44)

잘못 등록한 협력업체·계약·인증을 지운다. 행을 실제로 지우지 않고 **지운 표시만 남긴다.** 삭제한 건은 목록·상세·만료 현황·대시보드·알림함·엑셀에서 모두 빠진다.

## 사용 방법

- **계약·인증**: 계약 관리·인증 관리 목록 또는 업체 상세의 계약·인증 탭에서 행의 **삭제**를 누르고 확인한다.
- **협력업체**: 업체 상세 화면 오른쪽 위의 **삭제**를 누르고 확인한다. 삭제되면 목록으로 돌아간다.
- 관리자와 담당자만 삭제할 수 있다. 조회자에게는 삭제 버튼이 보이지 않고 서버도 403으로 막는다.

## 규칙

| 상황 | 동작 |
|---|---|
| 계약·인증을 삭제 | 그 건의 첨부 파일도 함께 지운 표시가 되고, 그 건에 대한 알림은 알림함에서 없어진다 |
| 갱신으로 등록한 건을 삭제 | 그 건만 지우고, 갱신 전 건이 다시 **현재 건**이 된다. 처리상태는 "미착수"로 돌아간다 |
| 이전 이력(갱신 전 건)을 삭제 | 409로 막는다. 현재 건을 삭제하면 이전 건이 현재 건이 되므로, 그 뒤에 다시 삭제한다 |
| 계약·인증이 남은 협력업체를 삭제 | 409와 함께 남은 건수를 안내한다. 이전 이력도 건수에 포함한다 |
| 계약·인증이 없는 협력업체를 삭제 | 업체에 올린 일반 자료도 함께 지운 표시가 된다 |

## API

| 요청 | 응답 |
|---|---|
| `DELETE /api/suppliers/{id}` | 204. 계약·인증이 남아 있으면 409 |
| `DELETE /api/contracts/{id}` | 204. 이전 이력이면 409 |
| `DELETE /api/certifications/{id}` | 204. 이전 이력이면 409 |

없거나 이미 삭제된 건은 404, 조회자는 403이다.

## DB

`V12__soft_delete.sql`이 `supplier`·`contract`·`certification`에 `deleted_at`, `deleted_by`를 추가한다. 세 엔티티는 `@SQLRestriction("deleted_at is null")`로 모든 조회에서 삭제된 행을 뺀다.

## 되살리기 (#72)

관리자는 **변경 이력**(업체 상세의 변경 이력 탭 또는 관리 > 변경 이력)의 삭제 기록 옆 **되살리기**로 지운 건을 되돌린다. 이미 되살린 기록에는 버튼이 없고, 기한은 없다. 담당자·조회자에게는 버튼이 보이지 않고 서버도 403으로 막는다.

| 상황 | 동작 |
|---|---|
| 계약·인증을 되살림 | 삭제할 때 함께 지워진 첨부도 다시 보인다. 그 전에 따로 지운 파일은 그대로다 |
| 갱신으로 등록했던 건을 되살림 | 삭제 때 다시 현재 건이 됐던 이전 건이 "갱신완료" 이력으로 돌아간다 |
| 협력업체를 되살림 | 삭제할 때 함께 지워진 일반 자료도 다시 보인다 |
| 협력업체가 삭제된 상태에서 그 계약·인증을 되살림 | 409. 협력업체를 먼저 되살린다 |
| 이전 건이 그 사이 다시 갱신되었거나 삭제됨 | 409. 현재 건이 둘이 되지 않도록 막는다 |

| 요청 | 응답 |
|---|---|
| `POST /api/suppliers/{id}/restore` | 204 |
| `POST /api/contracts/{id}/restore` | 204. 위 표의 경우 409 |
| `POST /api/certifications/{id}/restore` | 204. 위 표의 경우 409 |

삭제되지 않은 건은 404, 관리자가 아니면 403이다. 되살린 사실은 변경 이력에 "되살리기"로 남는다. 삭제하며 없어진 알림은 다음 만료 점검 때 기준에 맞으면 다시 만들어진다.

## 영구삭제 (#77)

관리자는 변경 이력의 삭제 기록 옆 **영구삭제**로 지운 건을 완전히 없앤다. **되돌릴 수 없다.** 확인 창에 함께 없어질 첨부 파일 수를 보여 주고 한 번 더 확인받는다. 담당자·조회자에게는 버튼이 보이지 않고 서버도 403으로 막는다.

| 상황 | 동작 |
|---|---|
| 계약·인증을 영구삭제 | DB 행과 그 건의 모든 첨부(기록과 서버 디스크의 파일)를 지운다 |
| 협력업체를 영구삭제 | 업체 행과 담당자·메모·업체 자료를 함께 지운다 |
| 삭제된 계약·인증이 남은 협력업체를 영구삭제 | 409와 함께 남은 건수를 안내한다. 계약·인증을 먼저 영구삭제한다 |
| 영구삭제한 뒤 | 변경 이력은 그대로 남고 "영구삭제" 기록이 추가된다. 되살리기·영구삭제 버튼은 사라진다 |

| 요청 | 응답 |
|---|---|
| `DELETE /api/suppliers/{id}/purge` | 204. 계약·인증이 남아 있으면 409 |
| `DELETE /api/contracts/{id}/purge` | 204 |
| `DELETE /api/certifications/{id}/purge` | 204 |
| `GET /api/admin/files/purge-count?contractId=` (또는 `certificationId`, `supplierId`) | 함께 없어질 파일 수 |

삭제되지 않은 건은 404다(먼저 삭제해야 영구삭제할 수 있다). 서버 디스크의 파일은 DB 삭제가 확정된 뒤에 지우며, 지우다 실패하면 경고 로그만 남는다.
